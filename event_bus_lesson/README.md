# Событийная шина в памяти

Отдельный урок, к чату на WebSocket не привязан. Поднимаем **мок S3** и **мок SQS** библиотекой **moto**: корзина и очередь живут в памяти процесса, аккаунт AWS не нужен.

Студент собирает пакет `event_bus`: «загружает» картинку, кладёт в очередь JSON о загрузке, консьюмер читает сообщение и печатает имя файла. Слои разведены по файлам: S3 не знает очередь, консьюмер не знает корзину, `main` только склеивает вызовы.

Расчёт на **~45 минут**.

## Как читать

1. Сначала [guide.md](guide.md) — зачем шина, кто продюсер, кто консьюмер.
2. Затем шаги по порядку. Не переходите дальше, пока не отметили «✅ Готово».

В каждом шаге:

1. **Задача** — что должно получиться.
2. **Теория** — своими словами, зачем так.
3. **Код** — какой файл пакета создать или заменить.
4. **Разбор** — что делает каждая часть.
5. **✅ Проверка** — запуск скрипта и ожидаемый вывод.

## Стек

| Компонент | Зачем |
|-----------|--------|
| boto3 | клиент AWS: те же вызовы, что к настоящим S3 и SQS |
| moto | перехватывает эти вызовы и отвечает из памяти процесса |
| S3 | хранит байты файла и отдаёт URL |
| SQS | хранит текст события, пока его не заберёт консьюмер |
