# Шаг 3 — Plan mode

**Предыдущий:** [step-02-prompt.md](step-02-prompt.md)

## Задача

Отдать промпт новому чату в plan mode и принять план только если он выдерживает проверку ниже. К правкам кода этот урок не переходит.

## Теория

Переключатель режима сидит в поле ввода. Нужен Plan, не Agent. Чат — новый: в старом уже лежит контекст другой задачи, и план начнёт «доделывать» её.

Агент в plan mode читает репозиторий и возвращает план. Пока вы не нажали принятие, файлы не меняются. Принятие — это разрешение писать код. Поэтому читать план нужно до кнопки, а не после diff.

Если плана нет, а сразу пошёл патч, режим был Agent. Остановите генерацию, файлы не принимайте, откройте новый чат.

## Код

В чат уходит целиком ваш текст из шага 2, без приписки «ну ты понял». После ответа сверьте план со своим контрактом.

Отказ пишете сами, тем же правилом, что и промпт: что не так, чего хотите вместо этого, и снова запрет правок. Два случая, которые встречаются сразу.

План называет файл вне `chat_service/` или сущность, которой не было в контракте. В отказе есть конкретный путь или имя (`app/models.py`, таблица для индикатора, `offset` вместо `before`) и просьба вернуть план только по вашему контракту.

План пересказывает задачу и не содержит списка файлов. В отказе одна претензия: дописать список и порядок. Спорить с реализацией в этом сообщении не нужно.

## Разбор кода

Отказ повторяет границу, а не вкус. «Мне не нравится» агент трактует как стиль и приносит тот же план другими словами. Имя лишнего файла оставляет ему конкретный вычерк.

Порядок внутри `chat_service` может отличаться от вашего: сначала репозиторий, потом роут, потом HTML. Это нормально. Поводом для отказа это не является.

Поводом является лишняя сущность, которой не было в контракте. Для фичи B это таблица и миграция. Для фичи A это `offset` вместо `before`. Для фичи C это правка личных сообщений или удаление.

## ✅ Проверка

- Режим чата был Plan, чат был новым.
- До принятия плана `git status` чистый относительно того, что вы не меняли сами.
- В плане есть список файлов, и все они под `chat_service/`.
- Контракт из промпта повторен: те же имена полей и те же коды, без второй фичи.
- Для B в плане нет миграции. Для A нет смены контракта на `offset`. Для C миграция есть только у чата, монолит не упомянут.
- План, который этого не выполняет, отклонён сообщением выше, а не принят «на посмотреть».
