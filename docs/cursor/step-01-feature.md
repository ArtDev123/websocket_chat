# Шаг 1 — Одна фича из трёх

**Дальше:** [step-02-prompt.md](step-02-prompt.md)

## Задача

Выбрать одну фичу. Две другие в этот промпт не входят. Запишите выбор одной строкой — она станет первым предложением промпта.

## Теория

Все три фичи живут в `chat_service`. User-сервис и RabbitMQ для них не нужны: личность уже приезжает событием `user.registered`, имя в кадре берётся из `user_profiles`.

История сейчас обрывается. `GET /rooms/{id}/messages` и `GET /dm/{user_id}` принимают `limit` (по умолчанию 50, потолок 100) и отдают последние строки. Параметра «старше этого id» нет, см. `chat_service/app/routes/messages.py`.

Сокет принимает `join`, `leave`, `message`, `dm`. Отдельного кадра «я печатаю» нет, см. `WsClientType` в `chat_service/app/enums.py`.

Сообщение пишется один раз. Поля «изменено» у `Message` нет, ручки правки нет.

## Код

Выберите одну строку и оставьте её у себя в заметке. Это ещё не промпт.

**A. Курсор истории.** К обоим списку комнаты и списку лички добавляется query `before` — id сообщения. Ответ — до `limit` сообщений строго старше этого id, в том же порядке, что и сейчас. Без `before` поведение прежнее. Чужой id из другой комнаты не подмешивает чужие строки. HTML при прокрутке вверх дорисовывает старые. User-сервис, брокер и таблица `messages` не меняются.

**B. «Печатает».** Клиент шлёт кадр `typing` с `room_id`. Сервер рассылает остальным в этой комнате кадр с username и гасит смысл сам по себе: хранить в Postgres нечего. Повторный кадр того же человека просто обновляет плашку на клиенте, клиент прячет её через 3 секунды тишины. В личку индикатор не входит. Миграции нет.

**C. Правка своего сообщения.** Автор комнатного сообщения меняет текст. Чужой автор получает 403, неизвестный id — 404, пустой текст — 422. В строке появляется `edited_at`. Тем, кто сейчас в этой комнате, уходит кадр с id, новым текстом и `edited_at`. История после перезагрузки показывает новый текст. Личка и удаление сообщений не входят. Нужна миграция только в базе чата.

## Разбор кода

A трогает чтение и HTML, схему не трогает. Её промпт должен удержать агента от «давайте заведём `page` и `offset`»: контракт уже назван как `before`.

B не имеет таблицы. Промпт, в котором не сказано «без миграции», часто получает таблицу `typing_state`.

C одна меняет схему и поэтому обязана назвать миграцию чата и запретить такую же правку в монолите `app/`. Иначе агент поправит оба дерева.

Общее для всех трёх: монолит `app/`, `user_service/`, ключ `user.registered` и тесты чужого сервиса в diff не входят.

## ✅ Проверка

- Выбрана ровно одна буква: A, B или C.
- Одной фразой можете сказать, что увидит человек в браузере.
- Можете назвать файл, который уже делает соседнее поведение (`messages.py`, `enums.py` или модель `Message`).
