# Разрез монолита — user, chat, RabbitMQ

Монолит из [урока про WebSocket](../README.md) уже умеет регистрацию, комнаты и сокет. Здесь тот же код раскладывается на два сервиса в корне репозитория. Общего пакета нет: каждый сервис копирует себе тонкий каркас и владеет своей базой.

Расчёт на **~95 минут**. Монолит при этом не удаляем: сервисы — новые каталоги рядом.

## Как читать

1. Сначала [guide.md](guide.md) — граница, компоненты RabbitMQ и почему логин не едет в очередь.
2. Затем шаги по порядку. Не переходите дальше, пока не отметили «✅ Готово».

В каждом шаге:

1. **Задача** — что должно получиться.
2. **Теория** — своими словами, зачем так.
3. **Код** — что создать или какой кусок монолита заменить.
4. **Разбор кода** — что делает каждая часть.
5. **✅ Проверка** — `curl` или UI брокера прямо сейчас.

Файлы, которые на разрезе не меняются, **копируются целиком** из `app/`. В шагах целиком приведены только новые файлы и те функции, которые пришлось переписать.

## Стек

| Компонент | Зачем |
|-----------|--------|
| Два FastAPI | user — личность, chat — комнаты и сокет |
| Два PostgreSQL | у сервиса своя база, чужих таблиц нет |
| Общий `JWT_SECRET` | чат проверяет подпись и не ходит в базу паролей |
| RabbitMQ | user публикует «пользователь зарегистрирован», chat пишет локальную проекцию |
| aio-pika | async-клиент, чтобы не блокировать uvicorn |
