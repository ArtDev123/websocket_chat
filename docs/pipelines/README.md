# Пайплайны — тесты, ruff и Docker для обоих сервисов

User-сервис и chat-сервис из [разреза монолита](../split/README.md) уже поднимаются отдельно. Здесь на каждый из них появляется проверка, которую GitHub запускает сам: линтер, тесты на своей базе и сборка контейнера.

Расчёт на **~50 минут**. Монолит и код сервисов не переписываем. Добавляются тестовая база, pytest, ruff и два workflow.

## Как читать

1. Сначала [guide.md](guide.md) — что такое пайплайн, зачем тестам чужая база и почему оба workflow стартуют на один push.
2. Затем шаги по порядку. Не переходите дальше, пока не отметили «✅ Готово».

В каждом шаге:

1. **Задача** — что должно получиться.
2. **Теория** — своими словами, зачем так.
3. **Код** — что положить в файлы.
4. **Разбор кода** — что делает каждая часть.
5. **✅ Проверка** — команда прямо сейчас.

## Стек

| Компонент | Зачем |
|-----------|--------|
| GitHub Actions | запускает проверки на push и на pull request |
| pytest | зовёт сервис как HTTP-клиент, без браузера |
| Отдельный Postgres на сервис | `user_test` и `chat_test`, не `user_db` и не `chat_db` |
| ruff | ловит сломанный импорт и неиспользуемое имя до тестов |
| Docker Compose | в третьей джобе собирает тот же образ, что на уроке |
